# Настройка: аккаунты, синхронизация, деплой на Netlify

Приложение из локального PWA стало многопользовательским: вход по email+паролю,
данные синхронизируются через Supabase, ник показывается сверху. Работает офлайн
(библиотека Supabase лежит локально в `supabase.js` и кэшируется).

---

## 1. Создать проект Supabase

1. Зайдите на https://supabase.com → New project (бесплатный тариф).
2. Дождитесь, пока проект развернётся.

## 2. Создать таблицу и политики

1. Supabase → **SQL Editor** → New query.
2. Вставьте содержимое файла `supabase-setup.sql` и нажмите **Run**.
   Это создаёт таблицу `profiles` и включает Row Level Security
   (каждый пользователь видит только свои данные).

## 3. Подтверждение email (включено)

Выбран режим **с подтверждением email**.
- Supabase → **Authentication → Providers → Email** → опция *Confirm email* должна
  быть **включена** (по умолчанию так и есть).
- Supabase → **Authentication → URL Configuration**:
  - **Site URL**: адрес вашего сайта (например `https://ваш-сайт.netlify.app`).
    Для локальной проверки можно временно поставить `http://localhost:8080`.
  - **Redirect URLs**: добавьте туда же адрес сайта (и `http://localhost:8080`
    на время разработки), чтобы ссылка из письма вела обратно в приложение.

> После регистрации пользователю приходит письмо. Пока он не подтвердит —
> войти нельзя (приложение покажет «Письмо отправлено… подтвердите регистрацию»).

## 4. Вставить ключи в приложение

1. Supabase → **Project Settings → API**. Скопируйте:
   - **Project URL** (вида `https://xxxx.supabase.co`)
   - **anon public** ключ
2. Откройте `index.html`, найдите блок «Мост к Supabase» (вверху, перед основным
   скриптом) и замените:
   ```js
   const SUPABASE_URL = "https://YOUR-PROJECT.supabase.co";
   const SUPABASE_ANON_KEY = "YOUR-ANON-PUBLIC-KEY";
   ```
   на свои значения.

> Анон-ключ **публичный по дизайну** — его не страшно держать в коде. Данные
> защищает RLS (шаг 2). **Никогда** не вставляйте сюда `service_role` ключ.

## 5. Локальная проверка

`file://` не годится (нужен http). Python не установлен — поднимите статику через Node:

```
npx http-server "D:\Системные\Desktop\my-project\waitertracker" -p 8080 -c-1
```

Откройте http://localhost:8080. Проверьте: регистрация → письмо → подтверждение →
вход → ник сверху → добавление смены → перезагрузка (данные на месте) → выход →
вход в другом браузере (данные из облака).

## 6. Деплой на Netlify

Это статический сайт — сборка не нужна.

1. Залейте проект в репозиторий GitHub (если ещё нет).
2. Netlify → **Add new site → Import an existing project** → выберите репозиторий.
3. Настройки сборки:
   - **Build command**: пусто
   - **Publish directory**: папка с `index.html` (корень репозитория или
     подпапка `waitertracker`, смотря как устроен репозиторий).
4. Deploy. После деплоя возьмите адрес `https://...netlify.app` и пропишите его
   в Supabase → URL Configuration (шаг 3): Site URL и Redirect URLs.

Никаких секретов в переменные окружения класть не нужно — анон-ключ публичный.

## Как это работает (кратко)

- **Локально-первый подход**: данные мгновенно пишутся в `localStorage`
  (ключ `waiter-tracker:<id пользователя>`), затем с задержкой отправляются в облако.
- **Синхронизация**: при входе приложение тянет облачную строку и сравнивает по
  времени изменения (`updated_at`). Кто новее — тот и побеждает (last-write-wins).
- **Офлайн**: без интернета приложение работает на локальных данных; изменения
  становятся в очередь и уходят в облако, когда связь вернётся
  (или при возврате на вкладку).
- **Безопасность**: RLS в Supabase — каждый пользователь читает/пишет только свою
  строку. Анон-ключ сам по себе ничего лишнего не открывает.

## Ограничения

- Конфликт правок с двух устройств офлайн разрешается по «кто последний сохранил»
  на уровне всего блоба — более старый набор правок может перезаписаться. Для
  одного пользователя на практике редкость.
- Время берётся с часов устройства; сильно сбитые часы могут повлиять на выбор
  «кто новее».
